## 二、四层保险（按重要性排序）

### 第 1 层：保住那串口令（最重要）

```
存放在：%APPDATA%\wechat-data-analysis-desktop\output\account_keys.json
字段：   wxid_example123456 → db_key
```

**这是唯一必须备份的东西。** 理由（已由技术文档确认）：

- **跨版本有效** —— 4.1.9 提取的密钥在 4.1.13 上依然能用（社区验证 27/27）
- **与账号绑定**，不随进程重启改变
- 只要它在，微信任意升级你都能重新解密

**行动：** 把这 64 位 hex 记到密码管理器（或离线加密文件）。
**建议同时备份**：`image_xor_key`（`0xC6`）和 `image_aes_key`，否则图片解不开。

⚠️ **别截图发人、别进云盘、别放聊天记录里。**

## 三、为什么"零驻留"不影响你

技术文档确认（见 [密钥提取技术报告.md](密钥提取技术报告.md)）：

> 微信 **4.1.10+** 引入「零驻留」：数据库密钥派生后即用即弃，稳态内存中不存在任何可寻形态。

这意味着**以后想重新扫内存取密钥会越来越难**。但——**你已经拿到口令了，而口令跨版本不变。**

所以正确的策略不是"以后想办法再取一次"，而是：

> **现在把口令和明文数据保存好，以后任何版本都能自己解密。**

## 五、可选加固

- **验证备份可用**：定期用 `wxarchive.py export` 跑一次，确认导出的 HTML 能打开
- **测试独立解密**：故意从加密原库解一次，确认口令仍有效
  ```powershell
  python wxarchive.py decrypt --db "<某个加密.db>" --key <hex> --out test\a.db
  ```
- **考虑打包成 exe**：避免以后 Python 环境变化导致脚本跑不了
- **多个账号**：每个 wxid 有独立口令，需分别提取备份
